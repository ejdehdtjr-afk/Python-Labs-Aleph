# 006. 대시보드 페이징 · 정렬 (인시던트 티켓 · 최근 이벤트)

작성일: 2026-10-01 · 대상: `_7_board_test`

---

## 0. 한 줄 요약

목록을 **20건씩** 끊어 보여주고, 표 **머리글을 누르면** 그 컬럼으로 오름/내림 정렬한다.
자르고 정렬하는 일은 **서버**가 한다 — 화면이 다 받아와서 자르면 21번째부터는 아예 볼 수 없다.

---

## 1. 왜 서버에서 자르나

화면(JS)이 100건을 받아 20개씩 잘라 보여주는 방법도 있다. 하지만

- 101번째 기록은 **어떤 방법으로도 볼 수 없다** (서버가 100건만 주므로)
- "총 73건 · 4페이지" 를 알 수 없다 → **마지막 페이지 버튼**을 만들 수 없다
- 기록이 쌓일수록 매번 100건을 받는다 (느려진다)

그래서 서버가 `page·per_page·sort·order` 를 받아 **그 페이지만** 꺼내고, 총 건수를 세어 함께 준다.

---

## 2. API 사용법

조회는 둘 다 **키 없이** 된다(수업 확인용). 쓰기는 그대로 관리자 키가 필요하다.

```
GET /api/security/incidents
GET /api/security/events
```

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| `page` | 1 | 1부터. `0`·음수·글자를 주면 1페이지로 보정한다 |
| `per_page` | 20 | 한 페이지 건수. **최대 100** (더 큰 값을 줘도 100) |
| `sort` | `created_at` | 허용 목록 밖이면 **400** (아래 3절) |
| `order` | `desc` | `asc`(오름) \| `desc`(내림). 그 외는 400 |
| `limit` | — | 예전 화면 호환용. 주면 `per_page` 로 받아들인다 |

필터는 결과와 **총 건수 모두**에 적용된다.

| 목록 | 필터 |
|---|---|
| 인시던트 | `status=open\|closed` · `student=` · `severity=Low\|Medium\|High\|Critical` |
| 이벤트 | `decision=allow\|deny` · `student=` · `severity=...` |

### 응답

```json
{
  "count": 20,          // 이번 페이지 건수 (예전 키 그대로)
  "incidents": [ ... ],
  "page": 1, "per_page": 20,
  "total": 73,          // 필터를 적용한 전체 건수
  "total_pages": 4,
  "sort": "created_at", "order": "desc"
}
```

### 직접 확인해 보기

```bash
# 2페이지 (21~40번째)
curl "http://localhost:5000/api/security/incidents?page=2"

# 오래된 것부터
curl "http://localhost:5000/api/security/incidents?sort=created_at&order=asc"

# 급한 것부터 5건
curl "http://localhost:5000/api/security/incidents?sort=severity&order=desc&per_page=5"

# 열린 티켓만 — total 도 열린 것 기준으로 줄어든다
curl "http://localhost:5000/api/security/incidents?status=open"
```

## 3. 정렬할 수 있는 컬럼 (화이트리스트)

| 목록 | 허용 컬럼 |
|---|---|
| 인시던트 | `created_at` `updated_at` `closed_at` `severity` `status` `event_count` `src_ip` `id` |
| 이벤트 | `created_at` `decision` `severity` `fail_count` `student` `src_ip` `id` |

목록에 없는 이름은 **400** 으로 거절한다.

```bash
$ curl "http://localhost:5000/api/security/incidents?sort=password"
{"msg": "sort 는 closed_at, created_at, ... 중 하나여야 합니다 (받은 값: password)."}
```

조용히 기본 정렬로 넘기지 않는 이유는 두 가지다.

1. 화면을 만들다 컬럼 이름을 틀리면 **바로 드러난다** (틀린 채로 "정렬되는 것처럼" 보이지 않는다)
2. 받은 문자열을 그대로 `ORDER BY` 에 넣지 않는다 — 허용 목록에 있는 **컬럼 객체**만 쓴다

---

## 4. 쉽게 틀리는 두 곳

### 4-1. 심각도는 글자순으로 정렬하면 안 된다

`severity` 는 글자다. 글자순으로 줄 세우면 이렇게 된다.

```
Critical < High < Low < Medium      ← 알파벳 순서
```

그래서 "급한 것부터(내림차순)" 를 누르면 **`Medium` 이 1위, `Critical` 이 꼴찌**가 된다. 정렬은 됐는데
뜻이 거꾸로다 — 표만 보면 알아채기 어렵다.

`controllers/pagination.py` 가 SQL `CASE` 로 서열을 매겨 푼다.

```python
SEVERITY_RANK = {'Critical': 4, 'High': 3, 'Medium': 2, 'Low': 1}

def severity_rank(column):
  return case(SEVERITY_RANK, value=column, else_=0)   # 모르는 값은 0 = 가장 낮게
```

### 4-2. 정렬 기준이 같은 행이 있으면 페이지가 겹친다

`created_at` 이 **똑같은** 티켓이 여럿일 때, DB 는 그 행들의 순서를 보장하지 않는다
(실행 계획에 따라 쿼리마다 달라질 수 있다). 그러면

- 1페이지에서 본 행이 2페이지에 **또** 나오고
- 어떤 행은 **아무 페이지에도** 안 나온다

해결은 간단하다. 1차 정렬키가 같을 때 쓸 **2차 정렬키로 `id`** 를 같은 방향으로 붙인다.

```python
query.order_by(direction(sort_map[sort]), direction(id_column))
```

`tests/test_pagination_sort.py::test_pages_do_not_overlap_when_created_at_identical`
이 생성시간을 전부 같게 만들어 25건을 넣고, 1·2페이지 합집합이 **중복 없이 25건** 인지 검사한다.

## 5. 화면 (`templates/dashboard.html`)

두 표가 같은 동작을 하므로 공용 함수를 `templates/partials/_table_pager.html` 한 곳에 두고
`{% include %}` 로 가져다 쓴다.

| 함수 | 하는 일 |
|---|---|
| `newTableState()` | 표 하나의 보기 상태 `{page, per_page, sort, order}` |
| `tableQuery(state, filters)` | 상태 + 필터 → 쿼리스트링 (빈 필터는 안 보냄) |
| `bindSortHeaders(thead, state, reload)` | 머리글 클릭 → 정렬 토글 |
| `paintSortHeaders(thead, state)` | 정렬 중인 컬럼에 ▼▲, 나머지에 흐린 ↕ |
| `renderPager(el, meta, go)` | `« ‹ 1 2 3 › »` 와 "총 73건 · 1 / 4 페이지" |

정렬 가능한 머리글은 이렇게 표시한다. `data-sort` 가 **없는** 머리글(사유·제목·조치)은 눌러도
반응하지 않는다 — 서버가 허용하지 않는 컬럼이라 누르면 400 이 되기 때문이다.

```html
<th data-sort="created_at" class="...">생성 시각</th>
<th class="...">사유</th>                        <!-- 정렬 불가 -->
```

### 필터·정렬이 바뀌면 1페이지로 돌아간다

3페이지를 보던 중에 필터를 좁히면 그 페이지에는 아무것도 없어 **"기록이 없습니다"만 뜬다.**
데이터가 사라진 것처럼 보이므로, 필터·정렬이 바뀔 때마다 `state.page = 1` 로 되돌린다.

## 7. 테스트

```bash
cd _7_board_test
python -m pytest tests/ -q          # 71 passed
python -m pytest tests/test_pagination_sort.py -q   # 25 passed
```

`tests/test_pagination_sort.py` 가 특히 못 박아 두는 것

- 기본 20건 / 마지막 페이지 나머지 / 범위 밖 페이지는 빈 목록(200)
- 0건이어도 `total_pages` 는 1 — "1 / 0 페이지" 같은 표시를 막는다
- `per_page=500` → 100 상한, `page=0`·`page=-3`·`page=abc` → 1페이지
- 심각도가 **서열**로 정렬되는가 (4-1)
- 생성시간이 같아도 페이지가 겹치지 않는가 (4-2)
- 필터가 `total` 에도 적용되는가
- 예전 `limit=` 이 그대로 되는가
- **화면에 실제로 붙어 있는가** — `/dashboard` HTML 에 페이저 자리·정렬 머리글이
  있는지, 그리고 화면이 쓰는 `data-sort` 값이 전부 서버 허용 목록 안인지

마지막 항목이 없으면 "API 는 되는데 화면엔 안 보이는" 상태를 테스트가 놓친다.

## 8. 함정: `flask run` 은 코드를 다시 읽지 않는다

```bash
flask --app app run --port 5003        # Debug mode: off → 자동 리로드 없음
```

이렇게 띄운 서버는 **파일을 고쳐도 반영되지 않는다.** 컨트롤러도, 템플릿도 그대로다.
그래서 "코드는 고쳤는데 화면이 그대로" 로 보인다. 확인 방법:

```bash
# 응답에 total·page 가 없으면 예전 코드를 들고 있는 서버다
curl -s "http://localhost:5003/api/security/incidents?per_page=3"
```

고치려면 서버를 **재시작**하거나, 개발 중에는 리로더를 켜고 띄운다.

```bash
flask --app app run --port 5003 --debug     # 파일을 고치면 자동 재시작
python app.py                               # app.run(debug=True) — 5000 포트
```
